# Drive HUD — Even Realities G2 운전용 HUD 플러그인

현대차 HUD(헤드업 디스플레이) 옵션에서 보던 정보를 Even G2 글래스에 띄우는 Even Hub 플러그인입니다.

| 현대 HUD 기능 | 상태 | 데이터 출처 |
| --- | --- | --- |
| 현재 속도 | ✅ | 휴대폰 GPS |
| 제한속도 표지 + 과속 경고 | ✅ | OpenStreetMap `maxspeed` (Overpass API) |
| 과속 단속 카메라 알림 | ✅ | OpenStreetMap `highway=speed_camera` |
| 턴바이턴 길 안내 (화살표 · 남은 거리 · 도로명 · 도착 시각) | ✅ | Tmap API(키 등록 시) 또는 OSRM 경로 + Nominatim 검색 |
| 시계 · 진행 방위 | ✅ | 휴대폰 |
| 크루즈 설정 속도, 차로 유지, 후측방 경고 등 차량 ADAS 정보 | ❌ | 차량 CAN 데이터가 필요해 휴대폰만으로는 불가 (OBD 동글 연동 시 일부 가능) |

## 화면 구성

화면은 하나로 고정돼 있고, 글래스 터치패드를 **두 번 탭**하면 종료합니다.

G2 화면은 시선보다 약간 위에 떠 있으므로, 모든 정보를 화면 **아래쪽 중앙의 한 덩어리**로 모았습니다. 도로를 보는 시선에서 가장 가깝고, 가장자리로 눈을 돌릴 필요가 없습니다.

```
                                       ┌──────────┐
                                       │ ─┼─┃─┼─  │  ← 미니맵: 주변 도로, 경로, 다음 회전, 목적지, 단속 카메라
                                       │  │ ▲ │   │
                                       └──────────┘
        테헤란로  3.0 km · 09:24 도착        ← 안내 중: 도로명·남은 거리·도착 시각 / 평소: 시계·방위
   ↱            46             (50)
 550 m         km/h          단속 600 m
 회전 안내      속도        제한속도 · 단속 카메라
```

미니맵은 진행 방향이 위로 오도록 돌아가며, 차는 아래쪽 가운데에 있어 앞쪽이 더 넓게 보입니다.

- 주변 건물: 가장 흐린 윤곽 (OpenStreetMap, 반경 400 m, 70 km/h 미만에서만 받아옴)
- 주변 도로: 큰길은 진하게, 골목은 조금 흐리게 (OpenStreetMap)
- 길 안내 중: 경로(가장 밝은 선, 주변 도로와 구분되도록 어두운 테두리), 다음 회전 지점(동그라미), 목적지(네모)
- 단속 카메라: 마름모
- 속도에 따라 축척이 바뀝니다: 50 km/h 미만 약 200 m 앞까지, 90 km/h 미만 약 300 m, 그 이상 약 480 m
- 글래스 전송량 때문에 3초에 한 번 갱신합니다

제한속도를 넘으면 속도에 테두리가 생기고 표지 테가 굵어집니다. 도로에 제한속도 정보가 없으면 앞에 있는 단속 카메라의 제한속도를 표지에 씁니다. 기준(+0 / +5 / +10 km/h)은 휴대폰 화면에서 고릅니다.

## 지도 데이터와 저장

제한속도·단속 카메라·미니맵 도로·건물은 OpenStreetMap 데이터를 약 1.1 km × 1.1 km 구역 단위로 받습니다.

- **국내 도로는 이 저장소에서**: `.github/workflows/map-tiles.yml` 이 매달 Geofabrik의 한국 OpenStreetMap 원본을 받아 도로·제한속도·단속 카메라만 구역별 파일로 잘라 GitHub Pages(`https://khj0209.github.io/even-g2-HUD/`)에 올립니다. 앱은 이걸 먼저 쓰고, 없거나 국외면 Overpass 공개 서버를 씁니다. 건물은 데이터가 커서 계속 Overpass에서 받습니다.
- 처음 한 번 저장소 Settings → Pages → Build and deployment → Source 를 **GitHub Actions** 로 바꿔야 올라갑니다.

- 차 주변 3×3 구역을 받습니다. 구역마다 요청은 두 번입니다: 도로(제한속도·단속 카메라·모든 도로를 한 번에)와 건물. 도로를 먼저 받고, 건물은 70 km/h 미만일 때만 받습니다.
- 받은 구역은 휴대폰(WebView의 IndexedDB)에 저장돼 앱을 다시 켜도 다시 받지 않습니다. 30일이 지나면 새로 받고, 최대 1,500구역까지 저장하며 오래된 것부터 지웁니다.
- **경로 미리 받기**: 길 안내를 시작하면 경로 양옆 약 500 m의 구역을 모두 미리 받습니다.
- **주변 미리 받기**: 휴대폰 화면의 "현재 위치 주변 3 km 받기" 버튼으로 받습니다. 도로는 반경 약 3 km, 데이터가 큰 건물은 반경 약 1.5 km까지만 받습니다.
- 차 주변 구역이 항상 미리 받기보다 먼저 처리됩니다.
- 공개 서버 3곳을 번갈아 쓰고, 한 번에 하나씩 최소 1초 간격으로 요청합니다. 서버가 혼잡으로 거절하면(429/502/503/504) 전체 요청을 15초, 30초, 60초… 최대 5분까지 멈췄다가 다시 시도합니다. 오류에는 서버별 실패 이유가 나옵니다.
- 미리보기 아래 "지도:" 줄에 받은 개수, 미리 받기 진행, 저장된 구역 수, 오류가 나옵니다.

## Tmap 제한속도

Tmap 키를 등록하면 제한속도를 Tmap "가까운 도로 찾기"(nearToRoad)로 받아 OpenStreetMap 값보다 우선 씁니다.

- 다른 도로로 들어서거나 같은 도로에서 400 m를 가면 다시 묻고, 최소 5초 간격을 둡니다. 추정 주행 중에는 묻지 않습니다.
- Tmap에 값이 없거나 실패하면 OpenStreetMap 값을 씁니다. 실패하면 1분간 묻지 않습니다.
- Tmap 약관상 받은 데이터를 24시간 넘게 보관할 수 없어 메모리에만 두고 저장하지 않습니다.
- 상태 줄에 조회 횟수와 오류가 나옵니다. 무료 사용량 한도는 SK open API 콘솔에서 확인하세요.

## 속도와 GPS 처리

- 정확도가 50 m보다 나쁜 위치, 중복·역순 위치, 순간이동처럼 튀는 위치(초속 70 m 이상)는 버립니다. 튀는 위치가 3번 넘게 이어지면 실제 이동(긴 터널 통과 등)으로 보고 받아들입니다.
- 속도는 휴대폰이 주는 도플러 속도를 쓰고 가볍게 다듬습니다(약 0.5초). 휴대폰이 속도를 주지 않으면 최근 3초 동안의 이동 거리로 계산합니다.
- 1 km/h 미만의 흔들림은 무시해 59↔60처럼 숫자가 깜빡이지 않게 하고, 3 km/h 미만은 정지로 표시합니다.
- **맵매칭**: 움직이는 중에는 위치를 가장 그럴듯한 도로 위로 붙이고(길 안내 중이면 경로 30 m 이내 우선, 아니면 진행 방향이 맞는 도로 20 m 이내), 진행 방향도 도로 방향을 씁니다. 나란한 도로 사이에서 왔다 갔다 하지 않도록 직전 도로를 조금 우선합니다.
- **터널 추정 주행**: 주행 중(약 11 km/h 이상) GPS가 2.5초 넘게 끊기면, 마지막 속도로 맞춰져 있던 도로(또는 경로)를 따라 계속 간 것으로 추정해 속도·회전 안내·미니맵을 이어 보여줍니다. 화면 윗줄에 "GPS 추정"이 붙고 휴대폰의 GPS 표시는 꺼집니다. 최대 2분 30초까지 추정하며, 추정 중에는 경로 이탈로 재탐색하지 않습니다. 데모 주행의 첫 구간에 가상 터널이 있습니다.
- 위치는 0.5초 간격으로 요청합니다(휴대폰이 지원하는 만큼만 빨라집니다).
- 글래스로 보낼 때 속도 이미지를 다른 모든 갱신보다 먼저 보냅니다.

## 개발

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173/?demo` 를 열면 GPS 없이 내장 데모 주행으로 HUD 미리보기를 볼 수 있습니다.

시뮬레이터(별도 터미널, dev 서버 실행 중):

```bash
npm run sim
```

실제 글래스(Even 앱 개발자 모드에서 QR 스캔):

```bash
npm run qr
```

테스트와 패키징:

```bash
npm test
```

```bash
npm run pack
```

`npm run pack` 은 `drive-hud.ehpk` 를 만듭니다. 업로드는 `evenhub login` 후 `evenhub create` / `evenhub upload` 를 사용합니다.

## 배포 (GitHub Actions)

`.github/workflows/release-beta.yml` 이 패키징 → Even Hub 업로드 → 베타 지정을 합니다. `app.json` 의 `version` 을 올린 뒤
GitHub의 Actions 탭에서 **Release to Even Hub beta** 를 실행하면 됩니다.

처음 한 번만, 맥에서 로그인한 뒤 로그인 정보를 저장소 시크릿으로 등록합니다.

```bash
npx evenhub login
```

```bash
pbcopy < ~/.config/evenhub/credentials.yaml
```

GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret 에서 이름을
`EVENHUB_CREDENTIALS` 로 하고 복사한 내용을 붙여넣습니다.

Even Hub는 로그인을 갱신할 때마다 이전 토큰을 폐기하므로, 워크플로가 갱신된 로그인을 시크릿에 다시 저장합니다.
이를 위해 GitHub → Settings(개인) → Developer settings → Fine-grained tokens 에서 이 저장소만 대상으로
**Secrets: Read and write** 권한을 준 토큰을 만들어 `EVENHUB_SECRET_WRITER` 시크릿으로 등록합니다.

- 워크플로가 로그인을 갱신하면 맥에 저장된 로그인은 폐기됩니다. 맥에서 직접 CLI를 쓰려면 다시 로그인하세요.
- 맥에서 다시 로그인하면 반대로 시크릿의 로그인이 폐기될 수 있으니, 그때는 `EVENHUB_CREDENTIALS` 도 새로 등록하세요.

## 구조

```
src/
  core/      타입, 좌표 계산, 표시 형식
  services/  위치(Even 앱 · 브라우저 · 데모), 도로 데이터(제한속도 · 카메라), 경로 안내
  hud/       화면 모델(view) → 컨테이너 배치(layout) → 그리기(draw) → 글래스/미리보기 출력
  app.ts     전체 조율
  main.ts    휴대폰 설정 화면
```

G2 제약에 맞춘 설계:

- 화면은 576×288, 이미지 컨테이너는 200×100 이하로 유지
- 글래스 글꼴은 크기 조절이 안 되므로 속도·표지·화살표는 비트맵으로 그려 전송
- 이미지 전송은 느리고 동시 전송이 안 되므로, 바뀐 컨테이너만 한 번에 하나씩(최신 값 우선) 전송

## 알아둘 점

- 제한속도·단속 카메라는 OpenStreetMap 데이터라 누락되거나 실제와 다를 수 있습니다. 태그가 없는 도로에서는 표지가 표시되지 않습니다.
- 기본값은 공개 데모 서버(OSRM, Nominatim)이며 현재 위치가 이 서버들로 전송됩니다. 휴대폰 화면의 "경로 안내" 설정에서
  [openapi.sk.com](https://openapi.sk.com)에서 발급받은 개인 Tmap 앱키를 입력하면 경로 탐색·목적지 검색이 Tmap API로
  전환되어 국내 도로 정확도가 더 좋아집니다. 키는 `localStorage`/Even 앱 로컬 스토리지에만 저장됩니다.
- 실제 글래스에서는 아직 검증하지 않았습니다(시뮬레이터 0.9.5에서 확인).
- 주행 중에는 휴대폰을 조작하지 말고, 항상 도로 표지판을 우선하세요.
